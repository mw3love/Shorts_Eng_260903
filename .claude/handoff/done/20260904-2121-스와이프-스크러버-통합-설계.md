## 배경

이전 세션(같은 날)에서 캘린더·오늘 스크러버·생성일순 카드 공급을 배포했다. 그 직후
사용자가 실기기로 써보며 두 가지를 짚었다:
1. 오늘 카운터가 스와이프에 안 움직임 → 트리거를 "채점"에서 "표시"로 되돌리고, 되돌리기가
   "봤다"는 사실도 함께 취소하도록 뒤집어서 해결·배포 완료(커밋 `a014adf`).
2. 스크러버 선이 본문 위에 겹침 + 카드 뽑는 순서 질문 → 레이아웃을 `#app`의 독립 flex
   행으로 옮기고, 뽑기를 완료도 가중치 랜덤에서 **생성일자 오름차순**(Notion에서 쓰던
   방식)으로 교체해 배포 완료(커밋 `589a758`).

그다음 사용자가 "양방향 스와이프를 없애고 싶다"(무조건 오래된 게 1번)고 요청 → 논의 중
사용자가 더 나은 관점을 제시함: **스와이프 뒤로가기와 스크러버 뒤로가기를 아예 같은
메커니즘으로 취급하자.** 스크러버는 그 메커니즘의 "빠른 스킵(여러 칸 한 번에)" 버전일
뿐이라는 것. 이 방향에 합의했고, 세부 설계까지 이 세션에서 이미 얘기가 끝났다 —
**아직 코드로 옮기지 않았다**(사용자가 "정리가 필요할 듯"이라며 다음으로 미룸).

## 합의된 설계(다음 세션에서 그대로 구현하면 됨)

핵심: `deck`/`idx`(라이브 알고리즘 큐)와 `todayList`/`peekIdx`(스크러버 전용 엿보기)라는
**두 개의 분리된 내비게이션 상태를 하나로 합친다.** 오늘 본 목록(`todayList`) 안에서의
위치 포인터 하나(`browseIdx`)만 남긴다.

- **스와이프 왼쪽(다음)**: 지금 라이브 끝(=`todayList`의 마지막)에 있으면 새 카드를
  당겨옴(지금 `advance`/`goNext`와 동일한 서버 호출·오늘목록 추가). 이미 과거로 가 있는
  상태면 `browseIdx`만 +1(스크러버로 앞으로 한 칸 드래그한 것과 완전히 동일 — 부작용 없음).
- **스와이프 오른쪽(이전)**: `browseIdx`를 -1. 스크러버를 손가락으로 딱 한 칸만 끈 것과
  같은 동작. `browseIdx === 0`(오늘 첫 카드)이면 무반응(오늘 범위 밖=논외, 나중에 얘기).
- **완료 버튼**: 지금 보고 있는 게 라이브가 아니면(=`browseIdx` < 마지막) 그 카드를
  라이브로 승격시킨 뒤 채점 — 이미 만들어둔 `promotePeekToLive()`를 그대로 재사용 가능.
  라이브 상태면 지금처럼 `advance()`.
- **되돌리기**: 지금 규칙 그대로 — 엿보기/browseIdx 상태와 무관하게 항상 "진짜 마지막
  라이브 액션"을 대상으로 하고, 결과(새 라이브 위치)로 화면이 넘어간다. undo 후
  `browseIdx`는 새 라이브 위치(=`todayList`의 새 마지막 인덱스)로 재동기화해야 함.
- **스크러버 드래그**: 지금 그대로(같은 `browseIdx`를 여러 칸 한 번에 옮기는 것뿐 —
  메커니즘 자체는 스와이프와 동일해짐).

## 아직 안 정한 것 (다음 세션에서 정리)

- "오늘" 경계를 넘어(어제 이전 카드) 오른쪽 스와이프하면 어떻게 할지 — 이번엔 논외로
  미뤄뒀다(사용자: "그건 나중에"). 지금은 무반응으로 막는 정도로 충분해 보임.
- 오른쪽 끝(과거)에서 스와이프 반응(살짝 저항감 줄지 아예 무반응일지)은 아직 안 정함
  — 이건 이번 통합 설계 전, "양방향 제거"만 논의하던 시점에 잠깐 나온 얘기라 통합 설계
  기준으로 다시 정리해야 함.

## 구현 시 손댈 곳

`public/index.html`의 `goNext`/`goPrev`/`peekAt`/`promotePeekToLive`/드래그 핸들러
(`scroller.addEventListener('pointerup', ...)` 안 `commit && dx < 0` / `dx > 0` 분기) —
현재 `dx > 0`(오른쪽=이전) 분기가 `goPrev()`를 부르는데, 이걸 "browseIdx -1"로 바꾸면 됨.
`goPrev()`·`peekPrev` 관련 DOM/CSS(`.peek-prev` 등)는 이번 참에 정말 필요한지도 같이
재검토(엿보기가 `browseIdx` 하나로 통합되면 프리뷰 패널 구조도 단순해질 수 있음).

## 코드 변경 없음

이 세션은 논의만 하고 끝났다 — 커밋할 코드 변경이 없다(마지막 커밋은 `589a758`,
이미 실제 배포에도 반영돼 있음). 다음 세션은 이 설계를 그대로 코드로 옮기는 데서
시작하면 된다.
