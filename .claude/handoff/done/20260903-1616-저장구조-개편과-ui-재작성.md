## 다음 작업 — 이 순서로

### 1단계. 저장 구조 개편 (선행 필수)

- Notion **원본 블록을 그대로 보관**하고 렌더 시점에 변환한다.
  이유: 앞으로 렌더링을 몇 번 바꾸든 재동기화가 다시는 필요 없다.
- 전량 1개 KV 값 → **인덱스 + 버킷(50장 단위)** 으로 분리.
  - 인덱스: 제목·차수·날짜·id만. 약 100KB → 폰에 통째로 내려도 되고, 모아보기 목록이 이걸 쓴다.
  - 버킷: 본문. 세션에 필요한 것만 읽는다.
- `sync:state`도 누적 카드를 들고 있지 말 것 — 버킷을 즉시 flush하고 커서만 남긴다.
  (이게 위 `503`의 추정 원인이다)
- ⚠ 카드별 개별 KV 저장은 **불가** — 무료 KV 쓰기 1,000회/일 제한에 1,323장이 걸린다.
- ⚠ 카드에 **파서 버전**을 박을 것. 없으면 증분 로직이 옛 포맷을 계속 재사용한다.

**검증:** `/api/sync`를 `done:true`까지 완주(약 30분, 배경 진행). 1,101에서 다시 막히면
CPU 가설이 틀린 것이므로 `wrangler tail`로 실제 예외를 확인할 것.

### 2단계. 렌더링 — 서식 살리기

우선순위대로:
1. **인라인 코드(백틱)** — 사용자가 AI 답변에서 직접 고른 형광펜이다. 이 프로젝트에서
   **가장 중요한 정보**이지 부가 서식이 아니다. `annotations.code`를 살려 하이라이트로 렌더.
2. **표** — 비교·유의어를 한눈에 보려고 사용자가 AI에 요청해 만든 것. 지금은 셀을
   `" — "`로 이어붙여 문장으로 뭉개고 있다. 진짜 표로 렌더할 것.
3. heading · bold · 목록 · 인용.
4. 본문 색을 `--muted`(회색)에서 읽을 수 있는 대비로.

### 3단계. UI 재구성

- 제목(`이름`)을 **항상 최상단 고정** — 1단·2단에서 위치가 바뀌면 안 된다.
- 전문 볼 때 제목·번역을 크게 반복하지 말 것(같은 정보 두 번).
- 탭 → **전문 바로**(2단 공개 폐기).
- 원본 쇼츠 링크는 아이콘으로.

### 4단계. 제스처 재작성

**폐기됨: 기존 "자동 채점 1제스처"(안 보고 위로=이해 / 보고 위로=모름).**
확정된 새 규약은 `CLAUDE.md`의 「UX 규약」 절에 표로 있다. 요약:
- 1단: 위/아래=다음/이전, 좌→우=이해, 우→좌=모름, 롱프레스=애매, 탭=전문
- 2단: 세로=스크롤, 끝에서 더 밀면 **현재 카드 앞면으로**(다음 카드 아님), 좌우=닫기
- 2단에는 채점 제스처 없음

⚠ iOS 롱프레스가 텍스트 선택·돋보기를 띄우므로 1단에 `-webkit-touch-callout: none`.

### 5단계. 진행 모델 교체

**폐기됨: "한 판 10장" 세션.**
- 메인 게이지 = `완료도 = 0` 잔량(빈 값 포함). 사용자가 Notion에서 굴려온 소거 모델을 잇는다.
- 채점 → `완료도` 한 칸 승급/제자리/강등, `상태`에 쉬움/적당함/어려움, `복습 횟수` +1.
- ⚠ 횟수와 차수를 **같이 올리지 말 것**(세 번 봐도 모르는 카드가 3차로 올라간다).
- 뽑기: `0차 70% + 때가 된 상위 차수 30%`. "때가 됨"은 `1차 3일·2차 7일·3차 21일`.
- ⚠ 정통 간격반복(SM-2/FSRS) 금지 — "밀린 47장" 부채감이 Notion 복습을 멈추게 한 원인이다.
  경과일은 강제가 아니라 **뽑기 가중치**로만.

### 6단계. 모아보기(목록 뷰) 신규

차수 탭(`0 / 1차 / 2차 / 3차`) + 검색 + 상단 "최근 본 것". 1단계의 인덱스를 그대로 쓴다.

## 밟지 말아야 할 지뢰 (이미 밟아본 것들)

- **행 수를 공개 페이지(`*.notion.site`)에서 세지 말 것.** 표 뷰가 lazy-load라 21행만
  보인다. 실제로 이걸 전수로 오독해 "21장짜리 작은 DB"로 설계할 뻔했다. 규모는 API의
  `databases/{id}/query` 페이지네이션으로만 판단한다.
- **무료 요금제 서브요청 50회/요청.** 카드 1장당 본문·표 조회 2회라 한 요청에 20장이 한계.
- **Windows curl(schannel)이 `workers.dev`에 간헐적 TLS 실패(`HTTP 000`)를 낸다.**
  Worker 장애로 오해하기 쉽다 — 검증은 브라우저(playwright)로 할 것.
- **신규 `*.workers.dev`는 TLS 인증서 발급에 수 분** 걸린다. 그 사이
  `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`는 정상이다.
- **`상태`와 `완료도`가 둘 다 `select`** 라 타입으로 구분 불가. 옵션 내용으로 판별할 것
  (`쉬움|어려`=난이도, `N차 완료`=진도). `완료도` 첫 옵션은 `0차`가 아니라 그냥 `0`.
- **크롬 확장의 재저장이 pageId를 churn시킨다** — 학습이력 키는 정규화된 제목이어야 한다.
  (함정 상세: `~/.claude/wiki/notion-페이지-덮어쓰기-재저장.md`)
- **동기화 루프는 오류 내성이 있어야 한다** — `503` 한 번에 루프가 통째로 죽어 두 번 날렸다.

## 참고

- 확정 설계 전량은 `CLAUDE.md`에 있다. 이 파일과 어긋나면 `CLAUDE.md`가 우선.
- `prototype.html`은 초기 조작감 테스트용 Artifact 스냅샷이다. 앱(`public/index.html`)과
  별개이고 동기화되지 않는다. 새 UI를 여기 반영할 필요 없다.
- 사용자는 영어 DB에 개인정보가 없다고 명시했다 — 데이터 공개 자체는 보안 이슈가 아니다.
