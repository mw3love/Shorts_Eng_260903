## 배경

라운드14 배포 후 사용자 UX 피드백 6건을 검토("일단 검토하고 의견줘") → AskUserQuestion으로
처리 순서 확인 → 원인이 명확한 버그(폰트 팝업 슬라이더 touchmove 간섭)와 단순 기능(소챕터/
챕터 목록 카드번호)만 라운드15로 즉시 반영·배포(`Version ID e8d420a6-2cf0-4ec7-87d3-8d6c7640f7f6`).
나머지 4건은 시각 비교가 필요해 사용자 확인대로 `design-bakeoff`로 분리, 아티팩트를
발행해 두었다.

⚠ **3번 축(챕터 행 "최고 N" 통합)은 베이크오프 도중 이미 별도로 확정·코드 반영·배포까지
끝났다** — 평가 중 사용자가 "최고N이 왜 필요한가"를 되물어 원인을 재조사(`handleAnswer()`,
`src/worker.js:646` — 시험에서 정직하게 "몰랐음"이라 답할 때 현재 점수만 내려가고 최고는
안 내려가게 지키는 안전장치였음)한 뒤, "상시 표시 유지 + R4(점수 옆 트로피 아이콘) 채택"으로
직접 결정. `Version ID b3c020fd-bab6-4e9c-b7ec-e7624c4c4e72` 배포 완료, 근거는
`~/.claude/design-system/projects/shorts-deck.md` 라운드5 참조. **아래 "다음 세션에서
할 일"은 남은 3건(1·2·4번 축)에만 해당** — 3번 축 관련 평가가 아티팩트에 남아있어도 무시할 것.

## 다음 세션에서 할 일

1. `Artifact` 도구 `action: "read_db"`로 해당 아티팩트 URL의 `ratings` 컬렉션을 조회해
   각 후보(`icon-E1`, `font-F2` 등 id)의 rating/comment를 확인.
2. 평가가 어느 정도 쌓였으면(전부 다 채워질 때까지 기다릴 필요는 없음 — 사용자가 준비됐다고
   하면 바로) 요소별로 재조합해 확정 스펙 도출 — `~/.claude/design-system/projects/
   shorts-deck.md`의 기존 패턴(라운드3·4가 "콘셉트 하나 통으로"가 아니라 "요소별 재조합"으로
   수렴했던 사례)을 참고.
3. 확정되면 `shorts-deck.md`에 라운드5(베이크오프 문서상 다음 번호) 기록 + 탈락 후보/이유
   기록.
4. `public/index.html`에 코드 반영 → 로컬 `wrangler dev` + Playwright 검증 → 커밋+배포
   (이 저장소는 라운드 루프 자동 커밋+배포 예외 적용 중, CLAUDE.md "작업 방식" 절 참조).

## 판단 기준

- 평가가 애매(비교 불가) 판정만 나온 축은 재베이크오프 없이 사용자에게 직접 "어느 쪽이
  나은지" 물어도 됨(전례: 라운드4 필터 토글 — 3안 다 애매 판정 후 사용자가 직접 대안 제시).
- 아직 평가가 하나도 없으면 사용자에게 리마인드만 하고 다른 작업으로 넘어갈 것 — 재촉하지
  않는다.
