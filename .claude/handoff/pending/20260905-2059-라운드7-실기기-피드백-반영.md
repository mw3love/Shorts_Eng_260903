## 지금 상태

라운드5·6이 **배포까지 끝났다**(`Version ID 7d6efa2d-8029-451d-937b-a018b8af1241`,
https://shorts-deck.shorts-deck.workers.dev). 커밋·문서동기화·wiki 기록 전부 완료 —
작업 트리는 깨끗하다(`.claude/settings.local.json`만 untracked, 무관).

**이 프로젝트는 「실기기 피드백 → 반영 → 배포」를 라운드 단위로 반복 중이다.**
`CLAUDE.md` 최상단이 항상 최신 라운드이고, 그 아래로 라운드6 → 5 → 4 → 3 → 2 순으로
쌓여 있다. **먼저 CLAUDE.md 최상단 라운드6 섹션을 읽고 시작할 것.**

다음 입력은 사용자가 아이폰으로 직접 써 보고 오는 피드백이다. 그걸 받아 라운드7을
진행한다. 아래는 그때 바로 쓸 수 있게 남기는 배경이다.

## ⓐ 라운드6에서 「미검증」으로 남긴 것 3건 (프록시검증)

로컬 `wrangler dev` + 브라우저 클릭까지만 확인했고, 실기기에서만 판정 가능한 것들:

1. **라이트박스 스와이프 다운 닫기의 손맛** — 기본 배율에서 아래로만 받고, 90px 또는
   플릭(300ms 안에 40px)이면 닫힌다. 임계값이 손에 맞는지는 써 봐야 안다. 상수는
   `public/index.html`의 `LB_DISMISS_PX` / `LB_DISMISS_FLICK_MS` / `LB_DISMISS_FLICK_PX`.
2. **하단 바와 홈 인디케이터의 실제 간격** — `max(6px, calc(env(safe-area-inset-bottom)
   - 8px))`로 safe-area를 8px 파고들었다. ⚠ **더 내리면 46px 원형 버튼 아래쪽이 iOS 홈
   스와이프 제스처 영역과 겹쳐 탭이 먹힌다** — "버튼이 가끔 안 눌린다"는 보고가 오면
   이 8px부터 되돌릴 것.
3. **프리페치가 셀룰러에서 카드 넘기는 속도를 따라가는지** — 소챕터를 열면 인접
   소챕터를 백그라운드로 받는다. 10장을 빠르게 넘기면 프리페치가 못 따라올 수 있고,
   그때는 캐시 미스 → 250ms 뒤 로딩 화면이 뜬다. "경계에서 가끔 로딩이 번쩍인다"는
   보고가 오면 프리페치 시점을 앞당기거나(소챕터 로드 직후 → 인접 2개까지) 지연
   임계를 늘린다.

## ⓑ 알고 있으나 이번 범위 밖으로 남긴 것 2건

**1. 상단 주소 칩이 본문 위에 겹친다**

라운드6에서 **하단만** 본문과 분리했다(`.stage`가 `bottom:var(--barh)`에서 끝남).
상단 주소 칩(`.subpos`)은 여전히 `position:absolute; top:safe-area` 오버레이라,
스크롤하면 본문 글자가 칩 뒤로 지나간다. 카드 상단에서는 `.cardtitle`의
`padding-top: safe-area + 62px`가 자리를 비워 안 겹치고, **스크롤했을 때만** 겹친다.

거슬린다는 피드백이 오면 하단과 같은 방식으로 처리하면 된다 — `.stage`에 `top`도 주고
`--topbarh`를 실측하는 식. 다만 칩은 26px로 작고 중앙에만 있어 하단 바와 상황이 다르니,
사용자가 실제로 거슬려 하는지부터 확인할 것(선제 수정 금지).

**2. 텍스트 드래그 선택 vs 스와이프 충돌 — 구조적 취약점이 그대로 있다**

`public/index.html`의 `MOVE_TOL = 10`(px)이 너무 작다. 현재 규약은 `pointerdown` 후
450ms(`SELECT_PRIME_MS`) 안에 10px 이상 움직이면 스와이프 트래킹을 시작하고
`setPointerCapture`를 거는데, **길게 누르는 그 450ms 동안 손가락이 10px만 흔들려도
발동해 iOS 네이티브 텍스트 선택이 그 자리에서 차단된다.** 한 번 걸리면 되돌릴 경로가
없다(`mode`가 세로로 판정돼도 캡처는 유지).

제목 고치기(`/api/retitle`)와 형광펜(`/api/highlight`) 둘 다 드래그 선택이 전제라,
"선택이 잘 안 된다"는 보고가 오면 여기가 1순위다. 저비용 개선 2개:

- `beginSwipeTracking()` 진입 조건에 `Math.abs(mdx) > Math.abs(mdy)` 추가 → 세로
  흔들림으로는 스와이프가 안 잡힌다
- 이미 선택이 있으면(`!document.getSelection().isCollapsed`) 트래킹 자체를 시작하지 않기
  → 선택 핸들 드래그를 뺏길 여지가 없어진다

## 작업할 때 밟지 말 것 (이 프로젝트 고유 함정)

- **`npx wrangler deploy`는 반드시 프로젝트 폴더 안에서** — 홈에서 실행하면 Windows
  레거시 정션 재귀 탐색으로 `EPERM: scandir` 하며 죽는다.
- **`wrangler dev` 전에 `node_modules` 확인** — 없으면 wrangler를 새로 받으려다 멈춘 것처럼
  보인다.
- **로컬 `wrangler dev`(플래그 없이)는 로컬 전용 미니 KV** — 실제 1,323장이 아니라 테스트
  카드 몇 장만 있다. 카드 수에 의존하는 검증(예: 스와이프 트래킹은 `studyCards.length < 2`면
  아예 리턴)은 **카드가 2장 이상인 소챕터에서 해야 한다** — 라운드5에서 1장짜리 소챕터로
  테스트하다 가드 검증이 헛돌았던 적이 있다.
- **`.lightbox`처럼 `display:flex`를 주는 요소는 `[hidden]`이 안 먹는다** — author CSS가 UA
  기본 규칙을 이긴다. `.클래스[hidden]{display:none}`을 따로 명시할 것(이 프로젝트에서
  `.navbtn`·`.examjudge`·`#viewStudy`·`.lightbox`로 네 번 밟았다).
- **제스처가 실기기서만 안 먹으면** `~/.claude/wiki/shorts-deck-모바일제스처-히트박스-touchaction.md`
  를 먼저 읽을 것 — `touch-action` 선언만 의심하다 2라운드 날린 기록이 있다.

## UI 변경만이면 재동기화 불필요

카드 데이터 포맷(`PARSER_VERSION`)을 안 건드렸으면 배포 후 `/api/sync?restart=1`을 돌릴
이유가 없다. 블록 포맷을 바꿨을 때만 필요하다.
