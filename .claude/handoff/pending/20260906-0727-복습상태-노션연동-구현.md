## 이번 세션에서 바로 이어할 일 (메인)

**Notion DB는 준비됐지만 앱 코드는 아직 이 속성에 아무것도 안 쓴다.** 다음 4개
옵션에 실제로 값을 쓰는 코드를 넣는 게 남은 작업이다:

| 옵션 | 트리거 |
|---|---|
| 미확인 (Not checked) | 기본값 — 코드에서 명시적으로 쓸 일 없음 |
| 확인함 (Checked) | "안다" 버튼 짧은 탭 — `handleAnswer()`, `worker.js:596` |
| 완전히 앎 (Mastered) | "안다" 롱프레스 → 보관 — `handleArchive()`, `worker.js:631` |
| 휴지통 (Trashed) | "안다" 롱프레스 → 휴지통 — `handleTrash()`, `worker.js:644` |

### 구현 시 판단 기준

- **패턴은 이미 있다.** `handleRetitle()`(`worker.js:714`)이 정확히 같은 모양이다 —
  Notion PATCH 시도하고, 실패해도 삼키고 `notionOk` 여부만 반환, KV 업데이트는
  그대로 진행. 세 함수 다 이 패턴 그대로 넣으면 된다. 실패해도 앱이 안 깨져야
  한다(로컬 KV가 진실의 원본이라는 원칙 유지).
- **pageId가 필요한데 지금 세 함수는 `key`만 받는다.** 클라이언트가 `card.id`도
  같이 보내도록 바꾸거나(`apiPostKey` 호출부 3곳 — `doArchive`/`doTrash`/`markKnown`,
  `public/index.html`), 서버에서 `K_INDEX`를 뒤져 `key`로 `id`를 역조회하는 방법
  중 택일. 클라이언트가 이미 현재 카드 객체(`card.id`)를 들고 있으니 전자가 더
  간단해 보인다.
- **속성 이름을 하드코딩하지 말 것**(CLAUDE.md 원칙, 이미 한 번 사고 난 전례 있음).
  `discoverSchema()`가 이 속성을 못 찾는 상태이므로, 옵션 내용(`확인함`/`완전히 앎`/
  `휴지통`이 존재하는 select)으로 찾아서 스키마에 추가할 것. `schema:v1` KV 캐시
  방식은 2026-09-05에 통째로 삭제된 전례가 있고 그 이유(캐시가 낡으면 조용히
  실패)도 문서에 남아있음 — 캐시를 다시 만들 거면 실패를 프런트에 드러내는 방식으로.
- **`handleAnswer()`는 카드 하나 판정마다 호출되는 매우 잦은 경로다.** Notion API
  초당 3회 제한이 있는데, 사용자는 "사람이 손으로 누르는 속도로는 어차피 그 안에
  안 걸린다"고 판단해 진행을 승인했다(라운드와 무관한 별도 대화 — 이 판단 근거를
  구현 시 그대로 신뢰해도 됨, 재검토 불필요).
- **"휴지통" 라벨은 진짜 삭제가 아니다.** 실제 Notion 페이지를 `archived:true`로
  넘기는 기존 로직(`handleTrashDelete()`, 사용자가 휴지통 화면에서 "완전 삭제" 눌렀을
  때만)은 그대로 두고 건드리지 않는다. 이번에 추가하는 건 그 전 단계의 시각적 라벨일
  뿐 — 이중 안전장치 원칙 유지.
- **낙관적 업데이트 패턴도 이미 정착돼 있다**(라운드9, 제목/형광펜). 이 세 액션도
  화면 반응은 즉시, Notion PATCH는 백그라운드(실패해도 토스트만, 이미 `doArchive`/
  `doTrash`가 그런 식으로 짜여 있으니 구조는 크게 안 바뀜 — PATCH 호출만 얹으면 됨).

### 검증 계획

- 로컬 `wrangler dev`는 로컬 KV를 쓰지만 **Notion API는 실제 프로덕션 DB를 그대로
  호출한다**(`.dev.vars`의 실제 토큰 + `wrangler.toml`의 실제 DB ID — 별도 테스트
  DB 없음). 로컬 KV에 `id:"FAKE-1"` 같은 더미 픽스처가 남아있어(과거 세션이 만든
  것으로 추정) 이걸로 테스트하면 안전하다 — 실제 Notion 페이지가 아니라 PATCH가
  그냥 404/무시되고 끝난다.
- 진짜 카드로 테스트할 땐 저장/적용까지 실행하면 실제 Notion 데이터가 바뀌니, 라운드7~9
  세션에서 했던 것처럼 "실행 후 즉시 원상복구" 절차를 따를 것.
- 커밋+배포는 이 저장소에 한해 사용자 확인 없이 자동 진행하기로 돼 있다(CLAUDE.md
  "작업 방식" 절, 2026-09-05 도입) — 로컬 검증 끝나면 바로 커밋+`wrangler deploy`.

## 남은 것들 (이번 세션에서 안건으로 나왔지만 착수 안 함, 우선순위 낮음)

이 항목들은 사용자가 "의견줘" 단계까지만 갔고 진행 승인은 안 났다 — 다음 세션이
먼저 물어보고 진행할 것, 임의로 시작하지 말 것.

1. **예문 누락 버그 — 원인 확인됨(직접증거).** `pageBlocks()`(`worker.js:215`)가
   최상위 블록만 가져오고 `has_children`는 표(table)만 재귀 처리한다. "예시:" 불릿
   아래 중첩된 진짜 예문 불릿은 애초에 안 가져와서 안 보인다. 고치려면
   `pageBlocks()` 재귀 일반화 + `compactBlock()`에 `children` 필드 + `blocksHtml()`
   중첩 렌더링 + `PARSER_VERSION` 상향(전체 재동기화 필요, API 호출 늘어 시간 더
   걸림). CLAUDE.md 라운드10 절에 상세 기록.
2. **Notion 웹에서 형광펜 텍스트가 빨간색이 안 됨** — 우리 PATCH는 `color:'default'`를
   명시적으로 보내는데(`toNotionRichText()`, `worker.js:204`) 실제로는 텍스트색이
   안 바뀜. 우리 앱 화면엔 영향 없음(자체 CSS로 그림), 순수 Notion 웹 전용 문제.
   원인 확인하려면 PATCH 직후 블록을 다시 GET해서 실제 저장된 `color` 값을 봐야 함
   — 아직 안 해봄. 낮은 우선순위.
3. **영상 링크 유무를 제목 옆에 아이콘으로 표시** — 제안만 하고 구현 안 함. 짧은
   탭이 유튜브로 가는지 안 가는지 지금은 알 방법이 없다(라운드11에서 링크 없으면
   탭을 막는 버그는 고쳤지만, "막혔다"는 시각적 신호는 아직 없음).
4. **`CLAUDE.md` 문서 비대화** — 현재 약 47,300자(관례적 기준 40,000자 초과, 여러
   번 플래그함). 옛 라운드(2~9 정도) 히스토리를 `docs/history.md` 같은 파일로 옮기고
   최상단엔 최신 라운드+핵심 지침만 남기는 정리를 사용자가 몇 차례 미뤄왔다.
